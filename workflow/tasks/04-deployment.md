# 第四轮：部署准备与完整验收

## 1. 背景

将已实现的网页与 FastAPI 形成可重复启动和验收的交付。HTTPS、持久化和唯一调度进程是部署要求，用户实际环境决定最终发布结果。

## 2. 当前仓库状态判断

本任务尚未执行。先确认前三轮应用与测试存在，检查现有部署文件、Git 改动和待验证事项。域名、服务器、账户与 iPhone 未提供时不虚构环境，先完成本地可验证的部署包。

## 3. 本轮目标

Docker Compose 或明确的等效启动方式、数据库持久化、同源 HTTPS 部署文档、备份 / 恢复步骤与完整验收证据。

## 4. 修改范围

项目 Dockerfiles、docker-compose.yml、代理配置、无真实密钥的配置示例、README、部署 / 验收文档及必要部署缺陷修复。

## 5. 禁止事项

不直接使用 / 修改用户凭据或已有 .env；不迁移 / 覆盖用户真实数据库做测试；不自动对未知服务器部署，不无关重构，不把 PostgreSQL 可配置等同于已验收，不把本地浏览器同步称为两台手机通过。

## 6. 具体任务

1. 前端构建后由静态服务器提供，业务 API 同源转发 FastAPI，正确处理 SPA 深链接 / docs / openapi / health / SW 路径。
2. 数据库挂载持久化目录，API 与独立唯一 worker 共享正确数据库；迁移为启动前显式步骤，避免多个进程同时执行迁移。配置 API / worker health 和失败日志。
3. 给出本地一套可复制启动命令、停止 / 更新步骤和 HTTPS 部署说明；环境示例只有变量名与占位值。说明手机访问电脑的局域网地址与 HTTPS 真机条件。
4. 提供 SQLite 备份 / 临时恢复演练，PostgreSQL 切换和 Alembic 说明；若实测 PostgreSQL，记录版本与结果，否则保持待验证。
5. 执行 ACCEPTANCE 各组，修复真实失败项；保证匿名 / 非成员 / 普通成员 / 管理员权限、双用户同步、刷新 / 重启、提醒抑制、冲突和安全区行为。
6. 用户已提供并授权真实部署目标时，先完成本地检查与可审查配置，再按已有授权部署并记录地址；缺少目标时仅列出部署所需最少信息，完整交付本地材料。

## 7. 验收标准

- 清洁环境安装、迁移、启动、健康检查与构建可复现；服务重启持久化成功。
- 本地同源访问、深链接刷新、API 优先代理、SW 作用域正确；唯一 worker 不因 API 多实例重复启动。
- 备份恢复在隔离数据库演练；密钥未进入前端产物和 Git。
- 完整列出 ACCEPTANCE 自动化、浏览器、两台手机、iPhone 锁屏、真实 HTTPS 和 PostgreSQL各项证据或待验证原因。
- ROADMAP 只勾选达到完成条件的项目，12/12 必须有真实全部证据。

## 8. 完成后 Claude Code 需要输出什么

可运行交付目录、启动 / 更新 / 回滚说明、访问地址、配置需求、验证结果与证据、未通过项、真实部署状态。给出项目范围内 diff 和剩余风险，交 Codex 最终审查；不夹带真实 token / 密钥 / 密码。
