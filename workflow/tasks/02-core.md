# 第二轮：宿舍、排班、打卡与记录

## 1. 背景

在已验收的真实登录基础上完成用户方案的核心业务闭环。业务规则与 API 以 SPEC 为准。

## 2. 当前仓库状态判断

本任务尚未执行。执行前确认第一轮代码、测试与进度证据存在；读取 git 状态及本轮相关文件。若第一轮未达标，先修复阻断项，不直接建立第二套工程。

## 3. 本轮目标

两个独立账号进入同一宿舍，管理员生成 30 天排班，本人打卡，其他用户刷新看到服务器结果；完成宿舍管理、周 / 月日历、首页及历史。

## 4. 修改范围

现有前后端宿舍 / 排班 / 记录模块、必要数据库迁移、tests、README 与进度证据。保持第一轮认证和工程结构。

## 5. 禁止事项

不在客户端计算最终排班；不删除历史，不允许代打卡，不依赖按钮隐藏做权限控制，不覆盖其他项目改动或真实 .env。不实现照片、积分、Android / 鸿蒙或推送，不无关重构。

## 6. 具体任务

1. 实现创建、邀请码加入、查询当前宿舍、配置修改、退出、移除、管理员转移及更新邀请码。所有对象查询校验成员归属；一次有效宿舍、今日退出限制与管理员规则在后端生效。
2. 排班服务独立于路由：锚点 / 顺序计算、补缺生成、显式未来重排、成员变更自动重排、今日 / 未来人工调整。返回版本号与更新摘要，唯一约束及条件更新防止冲突，事务失败不得部分更新。
3. 实现 duties 日期 / 状态 / 成员分页查询和 today 数据，统一 Asia/Shanghai、UTC 输出、昵称 / 任务快照与逾期展示。
4. 实现本人完成接口，验证有效成员、非未来、执行人、状态；使用原子条件更新。重复 409；逾期可以补打卡并保留真实时间。
5. 接通 Dorm.vue 的创建 / 加入 / 名单 / 管理设置；Home.vue 的今日任务与近期列表；Schedule.vue 的周 / 月切换和日期详情；History.vue 的筛选、分页与状态；Profile.vue 的昵称与退出宿舍入口。
6. 各修改请求提交中不可重复触发，409 显示冲突并刷新数据；重新进入、前台恢复和手动刷新从服务器获取，不长期复用陈旧 Pinia 内容。
7. 建立隔离临时库测试：外宿舍权限、并发加入、重复生成、未来重排保留历史、成员离开、管理员转移、午夜 / 截止时间、本人 / 他人 / 未来打卡、真实并发完成及版本冲突。

## 7. 验收标准

- ACCEPTANCE A 的核心业务项通过，特别是数据库唯一约束、原子完成、成员变更和版本冲突。
- 两个独立浏览器上下文使用真实接口完成创建 → 加入 → 生成 → 本人完成 → 对方刷新同步；保留证据。
- 前端类型检查 / 构建、已有 lint、后端业务测试通过；数据库重启保留任务。
- 六页面手机宽度检查，无横向溢出、无遮挡，加载 / 空 / 错误 / 逾期状态完整。
- 两台手机未实际执行时，只标浏览器同步通过，手机项待验证。

## 8. 完成后 Claude Code 需要输出什么

文件列表、业务默认规则落实情况、API / 权限改动、迁移说明、检查结果、双账号操作步骤与证据、未验证边界。更新进度 04–06；指出任何与 SPEC 不一致的实现，等待 Codex diff 审查。
