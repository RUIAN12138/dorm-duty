# 第三轮：PWA 与通知

## 1. 背景

核心业务通过后，先交付可用站内通知，再接入 Web Push。iPhone 主屏幕授权与锁屏接收是独立真机验收，不能以代码测试代替。

## 2. 当前仓库状态判断

本任务尚未执行；检查前两轮证据、依赖与业务 API，确认排班、完成状态和成员权限可用。读取 SPEC 通知规则与官方参考，锁定兼容版本，不混用 APScheduler 3.x 与 4.x API。

## 3. 本轮目标

PWA 安装资源、消息列表 / 未读 / 已读、独立提醒 worker、用户订阅 / 取消 / 测试 Push，具备真实 iPhone 验证路径。

## 4. 修改范围

frontend 的 manifest、图标、sw.ts、通知页面 / 我的；backend 通知 / push 路由与提醒服务、独立 scheduler 入口、必要迁移 / 测试；部署说明和进度证据。

## 5. 禁止事项

不把调度器放每个 API worker 内；不在加载时弹通知权限；不把 VAPID 私钥写仓库、前端或日志；不缓存个人 API，不离线伪打卡，不谎称提供商 accepted 等于手机收到。无真机 / HTTPS 不勾选锁屏成功。

## 6. 具体任务

1. 首先实现本人消息分页、未读数、幂等已读与页面入口。数据库约束隔离他人消息，取消提醒保留可审计历史。
2. 独立 APScheduler 3.x worker 每分钟扫描，启动补查最近 60 分钟，三个提醒时间、唯一键去重、完成抑制与成员变更取消规则均按 SPEC。同时补齐滚动 30 天缺失任务，复用业务服务。
3. 使用 vite-plugin-pwa injectManifest，建立独立 SW TS 配置，precache 静态资源、清理旧缓存、提供更新提示；生成真实 PNG 主屏幕图标和 maskable 图标，Manifest 和 apple-touch-icon 完整。
4. 实现 Push capability 检测、明确的主动授权按钮、VAPID 公钥查询、服务端订阅 / 取消 / 本人测试，鉴权与频率限制。未配置密钥时站内消息仍正常，界面解释 Push 不可用。
5. worker 落库提醒后按设备记录发送 / 重试状态，发送前复查任务；最多 3 次重试、处理 404/410、稳定 tag；处理退出登录和共享设备账号切换。
6. SW push 展示通知，notificationclick 聚焦 / 打开同源安全任务路由；身份到期先登录。未安装、拒绝、不支持、离线均有可理解提示。
7. 可注入业务时钟覆盖三时间点、重复扫描、完成与退出抑制、窗口补查、设备失败 / 重试；HTTP 测试模拟推送提供商只代表后端逻辑验证。

## 7. 验收标准

- 类型检查 / 构建 / 现有 lint、通知与 worker 测试通过；构建产物有有效 manifest、图标和 SW。
- 两次扫描只产生一条同任务 / 接收人 / 类型的站内消息，完成后不继续未完成提醒；worker 重启规则可复现。
- 订阅归属、取消、410 停用、逐设备有限重试、消息点击与离线提示有证据。
- 有 HTTPS 与 iPhone 时完整执行 ACCEPTANCE C，记录型号、版本、主屏幕、锁屏收到与点击行为；缺条件时留下准确操作步骤，并保持 07/09 真机部分待验证。

## 8. 完成后 Claude Code 需要输出什么

文件与配置变更、运行唯一 worker 的命令、通知规则 / 补查限制、测试结果、前端产物检查、真实手机证据或待验证清单。输出环境变量名称而非密钥；更新 07–09 的实际状态，等待 Codex 审查。
