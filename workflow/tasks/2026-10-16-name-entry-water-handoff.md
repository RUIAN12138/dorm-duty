# 本轮执行任务与复核边界

## 1. 背景

用户体验报告指出轮序、提醒及身份入口问题，随后明确选择：正式成员输入正确名字进入；抬水新轮序立即按最近完成者重算待办；真实交接后首次进入抬水页播放一次老虎机式姓名滚动。

## 2. 当前仓库状态判断

从干净、同步的 main（1ea5f74）创建 `codex/name-entry-ux-audit`。正式运行仍为 v31。本轮直接实现用户追加要求，无外部执行代理。既有开放 PR #24 不属于本轮。

## 3. 本轮目标

实现姓名入口后端校验、真实抬水重排、一次性姓名交接反馈，并修明确的轮序上下文及提醒可发现性问题。

## 4. 修改范围

Vue GuestHome / ChoreBoard / 轮序 / 提醒组件；Node 与 Worker 共用 chores/backend；对应隔离接口和浏览器验收、CI、产品说明。新增 WaterHandoffName 与本机已读轮次记录模块。

## 5. 禁止事项

不改用户宿舍数据、历史完成记录、密钥 / .env；不更换黑白风格；不把姓名当密码；不自动给普通成员创建者权限；不改一次点击撤销和连续敲击规则；不把浏览器检查写成实体设备送达或帧率验收。

## 6. 具体任务

1. 名字匹配成功才领取身份，匿名邀请码不泄漏正式名单，旧 ID 请求不可绕过。
2. 保存新序后仅更新抬水待办与旧提醒，使用既有版本事务处理并发，保留完成历史。
3. 从实际完成事件触发名字滚轮；所有设备首次看到新交接播放，轮询 / 切页 / 刷新不重播，减少动态直接结果。
4. 轮序跟随任务、预览待抬水人；提醒时间开关关闭时仍可见；进度显示总人数，刷新和消息文案准确。

## 7. 验收标准

姓名错误 / 无姓名 / ID 与姓名冲突不签发会话；跨宿舍 / 他人撤销仍拒绝。重排后服务器与名单预览一致，旧身份不能完成已转交任务，并发仅一个待办。滚轮固定占位、最终真实下一人、无重复。两独立身份刷新和切宿舍能恢复。所有必需构建 / CI 通过后再合并，正式发布前先备份并验证历史。

## 8. 完成后需要输出

实际改动、所运行检查与证据、PR、是否正式部署，明确仍待真机与 SSH 的边界。剩余体验问题记录于 `docs/NAME_ENTRY_WATER_HANDOFF.md`，不宣称已经全部解决。
