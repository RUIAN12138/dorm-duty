# 前端交互与视觉验收约定

## 1. 背景
用户强调每个可操作按键必须有反馈，状态更换必须连续过渡。保留黑白、大字、留白，重点是手机触感和视觉稳定，不做游戏化、不堆说明小字。本文件作为后续修改必须回查的约定。

## 2. 当前仓库状态与问题
从 main e1204ab 开始，分支 codex/completion-motion-contract，工作区初始干净。完成组件虽保留 is-round，但背景缩放时180ms就淡掉、成功回执立即变灰，弱化实际形变；完成/未完成文字与图标直接替换。任务选项勾选后宽度增加，窄屏存在重新换行并带动居中区域位移的风险。全局 button:disabled 另会将整个请求中按钮降至45%透明度；任务标题以任务ID为动画key，整轮更换ID时同一文案也被重复位移。上一轮鼓励只有淡入。

保留式优化：DESIGN_VARIANCE=3、MOTION_INTENSITY=6、VISUAL_DENSITY=2。这里是日常业务工具，只采用 taste skill 的保留式审计，不套用营销页结构、不更换主题字体、不增加图片背景。

## 3. 本轮目标
| Before | After | Why |
| --- | --- | --- |
| 胶囊淡掉后出现圆 | 两端圆帽向中心合拢、中心收缩，形成连续圆形 | 形变真实可见且不改外部占位 |
| 收圆期间回执立即改色 | 收圆保持黑色、成功描勾、之后展开已完成态 | 明确动作顺序 |
| 完成与撤销忙碌状态共用 | 撤销不收圆、不画勾、不放粒子，文案反向过渡 | 回到原始待办状态 |
| 任务选项勾选增加宽度 | 固定轨道与预留图标位 | 避免换行和整页抖动 |
| 鼓励只淡入、靠近底栏 | 提示上移，外层固定位置、内层缩放上浮弹出 | 轻提示有动作，但不推挤页面 |

## 4. 修改范围
CompletionAction、ChoreBoard、全局按压兜底、针对性逐帧和手机视口回归。保留 Vue、Vant、Motion for Vue、Reka、现有粒子；不增加运行时依赖。后端、身份、轮序、历史和通知接口不变。

## 5. 禁止事项
不移除既有交互以换取静态测试通过。不动画化布局宽高，不让页面祖先缩放，不用模糊。撤销只需再次点击已完成按钮，不新增独立撤销。失败不能显示成功反馈。遵守减少动态效果、键盘与后台终态规则。

## 6. 已回顾的资源与提示词
### 资源
- Galaxy（uiverse-io/galaxy）：已有按钮填充、描勾、加载、输入、分段滑块、箭头六类适配，来源及许可证见 UIVERSE_COMPONENTS.md。本轮继续用描勾与轻量触感。
- Motion for Vue / Reka UI：统一可中断运动与弹层语义，一个元素同一属性只用一个驱动。
- React Bits / Vue Bits：Stack、Carousel、Dock、ClickSpark、CardSwap、CountUp 的层次、跟手、局部反馈思路；本轮读取本机 ClickSpark、Dock、Carousel，自行以 Vue/CSS/WAAPI 实现，不引入 React。
- 先前用户给过 zackha/habit、donetick/donetick、arminBM/4us-habit-tracker、daya0576/beaverhabits、Hzy0913/mpvue-calendar、iSoron/uhabits、louismerlin/concrete.css、any86/any-touch、the-entertrainer/you-vs-who、HabitRPG/habitica：保留移动布局、信息层级、手势分层与样式一致性参考；不因此新增积分、XP、游戏化或复制 GPL 代码素材。
- 本机 awesome-design-md、math-curve-loaders、KnowledgeBase 索引路径缺失，不能声称已读取。

### 用户提示词的保留与覆盖关系
- 按压微缩/压扁回弹：所有可操作控件必须有反馈；已有拖动/运动控件保留自己的驱动，普通控件补同一套轻反馈。
- 流体胶囊→圆→画勾→粒子：完成操作必须可见；成功回执前只处理中，失败回胶囊，撤销不庆祝。
- 弹性抽屉：底部出现、跟手、短拉回弹、快甩关闭，中断可反向；两页任务详情均从底部进入。
- 叠卡/列表交错：保留厚度、可拖动与右到左渐显；收起也保留逐项淡出与向标题方向回收，260ms 位移 + 最多90ms交错，底层叠卡同时渐显；条目退出前保留滚动范围，但下方分组必须在退出期间同步向上跟随，不能等退出结束才开始归位。结束后以相同视觉位置接入实际布局。验收必须取条目仍可见时的相邻分组位置，不只检查条目最后消失。
- 圆环增量/+1/计数：首页小环进页直接显示终态，只对本机新完成回执做增量反馈；展开轮次保留原版完整圆环的累积展示与 +1 吸收，名单独立从右向左渐显，不随 +1 节拍等待。形变只作用圆环，不能震整页。不得用横向进度条或纯文字替换 RoundProgress；组件级测试通过不足以保证页面仍然接入，必须同时验收 ChoreBoard 的真实入口。
- 统计卡片/日期轮播：手指未松开可看到邻卡/邻月，方向可反转，小点联动。
- 共享展开/圆形扩散：已被用户后续明确的“底部抽屉、页面渐隐渐显”覆盖，不重新恢复旧跳转方式。
- 3D倾斜、高光、磁吸图表、光晕：仅用于合适局部场景，不为凑效果加图表或全页发光。
- 惯性时间滚轮：保留 TimeWheel；催促姓名保留局部木鱼形变、波纹、浮字；抬水交接保留一次性老虎机。
- 头图/数字卡叠放、建议胶囊等：作为可选参考，未落地的不得写成已实现。

完成时先收圆，收到新的成功回执后描勾和局部粒子，再展开已完成态；之后在不遮挡内容的空位弹出鼓励。窄屏和整轮推进时保持标题/主按钮位置；按类别维持选中项，不因任务 ID 换轮回到另一类。同一类同文案的标题不因任务ID变化重新位移，抬水老虎机自己负责姓名运动，不叠加标题平移。撤销后重打不会复用旧成功回执。已有运动的导航、排序、催促、日期和 Motion 按钮不叠加全局缩放。

## 7. 验收标准
- 实际页面逐帧检查形变的中间位置、成功描勾、标签过渡；不能只断言 class 存在。
- 完成前后以及撤销期间，标题、任务选项、主按钮外占位、底栏和 scrollY 保持稳定；覆盖320/390/430px及多项完成。
- 撤销过程不存在 is-round 和成功粒子，失败恢复已完成态。
- 鼓励在导航上方更高的位置弹出，内层有 opacity/transform 动画，外层不改变布局，不与主操作重叠。
- 普通按钮有统一轻按压，导航/日期/排序/催促/Motion按钮保留各自专属反馈，不叠加缩放。
- 真实接口、身份与历史不回归；浏览器触摸与WebKit通过，不将模拟称为实体手机帧率验收。

逐帧回归：`node scripts/check-completion-experience.mjs`、`DORM_BROWSER=webkit node scripts/check-completion-experience.mjs`。覆盖320/390/430px、多项累积完成、完整轮次推进、旧回执/失败撤销、小按钮按压、减少动效。可设 `DORM_CAPTURE_VIDEO=1` 输出隔离数据下的录屏。

## 8. 完成后输出
具体恢复的交互、逐帧证据与布局验证、可视截图/录屏、PR与发布校验。后续更改先回查本文件和用户最后选择，再动组件。
