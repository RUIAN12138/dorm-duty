# 创建者权限恢复

当前功能已在源码和本地实现，正式网站仍为 `20261014-invite-gate-v17`；本轮按用户要求暂不发布到服务器。

## 保存与使用

在原创建设备进入正式宿舍，打开「… → 管理恢复码」，点击「生成恢复码」，复制并保存。服务器不保存原码，再次打开只显示设置状态；恢复码不会自动写进浏览器存储或网页地址。

换设备或清除网站数据后，在入口点击「恢复管理权限」，输入宿舍邀请码和已保存的恢复码。也可以先正常加入宿舍，在「…」菜单中打开恢复入口。成功后进入创建者身份，当前设备保存管理会话，刷新无需再恢复。

未提前生成或未保存恢复码时，需要先在仍拥有管理权限的设备上生成。游客模式不能生成恢复码；普通成员不能通过选中创建者名字获得管理权限。

重新生成需要再次确认，旧码立即失效。更换邀请码后，应使用新邀请码和原恢复码。宿舍转移管理、创建者退出或成员角色变更后，旧创建者不能再凭原码取得权限。

## 接口与存储

- `GET /dorms/recovery`：创建者查询是否已设置及版本，不返回原码或哈希。
- `POST /dorms/recovery`：创建者提交 `expected_version`，生成新码；并发或旧版本返回 409。
- `POST /guest/recover`：提交 `invite_code` 和 `recovery_code`，验证后签发创建者设备会话。
- 新增迁移 `0005_creator_recovery.sql`，只增加恢复信息表和索引，不改已应用迁移或历史记录。

恢复码为 32 字节随机值，以 64 位十六进制展示，数据库只保存 SHA-256 哈希。恢复时在同一写入中检查当前创建者、有效成员、角色及所属宿舍；生成时重新检查管理会话和版本。响应不缓存，恢复码不放在 URL 中。

## 验证

运行 `node site/scripts/check-creator-recovery.mjs`。隔离数据库检查包括成员权限、错误码、跨宿舍、并发生成、旧码失效、角色 / 宿舍变更、退出会话竞争、邀请码更换、历史宿舍范围和迁移保留完成记录。浏览器与 CI 的实际验收结果见当前进度；本地验证不等于正式网站已上线或真机已验收。
