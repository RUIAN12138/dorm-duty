# 列表收起、统计分页点与完成提示

## 1. 背景
用户反馈列表卡片收起卡顿、统计分页点切换不流畅；要求完成打卡后在导航栏上方空位淡淡显示“你真棒👍！”。

## 2. 当前仓库状态
从 main bb7fe13 开始，分支 codex/calendar-collapse-feedback，工作区初始干净。只改前端和针对性回归，不动生产数据、身份、轮序和推送。

## 3. 本轮目标
| Before | After | Why |
| --- | --- | --- |
| 退场一开始记录脱离文档流，列表滚动范围马上缩小 | 保留占位至全部卡片退场后统一收拢 | 避免浏览器提前钳制滚动位置 |
| 分页点选中背景在换卡后突变 | 相邻点按拖动进度交叉渐显 | 卡片与指示器同时响应 |
| 顶部黑色完成提示条 | 导航上方无背景轻提示 | 满足简约、低干扰反馈 |

## 4. 修改范围
RecordTimeline、CompactRecordList、SwipeCardDeck、ChoreBoard、check-focus-compact 及说明。现有 Vue、Vant、Motion 依赖不变。

## 5. 禁止事项
不新增游戏化、不改任务算法、不删撤销能力、不动画化高度/宽度、不加模糊、不触碰密钥及本地凭据。

## 6. 具体任务和来源
加载 frontend-design、emil-design-eng；参考本机 react-bits Stack 的手势与层次。awesome-design-md、math-curve-loaders、KnowledgeBase 索引路径未找到。保留记录逐项右到左入场；收起时固定占位，退场完成统一布局，分组用 transform FLIP；分页点只动 opacity/transform；服务端成功回执触发提示，失败和撤销不播放。已完成按钮仍可再次点击撤销。

## 7. 验收标准
- 7 条长列表收起时，退场期间保留原占位，结束后无幽灵卡片；快速重新展开也恢复正常。
- 退场最多200ms、统一收拢180ms，完整收起反馈不超过380ms，避免保留占位造成等待感。
- 统计滑动中相邻点具有连续中间透明度，回弹和循环切卡终态正确。
- 完成后提示文案完全匹配，位于导航上方且不遮挡操作；无背景和交互按钮，自动消失，误触可再次点击已完成撤销。
- 失败不显示鼓励；减少动效模式可用；Chromium 触摸事件和 WebKit 回归通过。

## 8. 完成后输出
说明修改、浏览器和构建验证、PR、发布与历史完整性检查，物理手机动画体验单独注明。
