# 日历触摸、叠卡与记录动效修复

## 1. 背景

用户反馈统计叠卡在手机上完全拖不动，列表展开/收起不自然，详情最末成员标记偶发缺失；要求从右向左逐项渐显、叠卡有厚度与立体感、日详情带底部抽屉与内部卡片入场。

## 2. 当前状态

从 main `5a0f884` 开始，分支 `codex/calendar-touch-layering`。复现保留在 `/tmp/dorm-touch-before.json` 与 `/tmp/dorm-touch-trace.json`。原鼠标检查通过，但 Chromium CDP 的真实 touchStart / touchMove 失败。原因：隐式捕获从文字转移到 stage 时，子元素冒泡的 lostpointercapture 被误当成取消；随后 stage 主动放掉捕获。

## 3. 本轮目标

| Before | After | Why |
| --- | --- | --- |
| 子元素丢失隐式捕获时终止整个手势 | stage 仍持有捕获则忽略子元素转移通知 | 手机手势可以连续跟手 |
| 首尾只回弹 | 两向循环浏览四类卡片 | 避免第一张向右无结果的误解 |
| 薄纸样式的平面旋转 | 透视、Z层次、双层底边与轻投影 | 明确前后距离和实体厚度 |
| 记录首次挂载无动画，偏移很小 | 开启 appear，44px从右向左逐项渐显 | 与用户指定的渐进入场一致 |
| 离场立即绝对定位且坐标未固定 | 捕获旧位置后原位退场，相邻日期用FLIP位移 | 减少收起时跳位和重叠 |
| 记录头像依赖SVG图片请求 | 详情、列表使用已打包内联像素路径 | 避免图片请求与解码依赖 |
| 日期详情未明确bottom，内容挤在同一滚动面板 | 明确底部抽屉，长列表内部滚动 | 最底记录和标记保持可达 |

## 4. 修改范围

SwipeCardDeck、RecordTimeline、CompactRecordList、ChoreRecordRow、ChoreCalendar 及针对性浏览器回归。无后端、数据库迁移、身份、通知或轮序业务修改。

## 5. 禁止事项

不改写历史，不取消历史修正与撤销权限，不加入额外功能说明小字，不引入模糊背景或新的第三方运行时。像素标记保持原100个图案与配色。

## 6. 具体实现与资源

已加载 frontend-design、emil-design-eng；读取本机 React Bits Stack 的前后层次和手势组织，仅借鉴思路。awesome-design-md、math-curve-loaders 目录仍不存在。入场 transform / opacity 交错32ms，位移44px，时长300/260ms，延迟上限8项。离场固定旧坐标，短距离向右淡出，日期分组通过位置FLIP缓动。系统减少动态效果和键盘仍直接到终态。

叠卡在实体面层外绘制两层底边，卡片前后以 translateZ 区分，拖动时加轻微Y轴旋转；触摸、鼠标共用识别逻辑，但测试分别覆盖。内联SVG来自现有 member-mark-paths，已核对100个标记全部有路径。

## 7. 验收标准

- 真实触摸事件连续拖动时位移非零，松手换卡；首尾两向循环，多次滑动不取消或误切底页。
- 后卡持续可见，面层、底边和层距独立；四种手机尺寸时间内容不裁切。
- 列表和详情均首次逐项从右向左渐显；收起时每项保留旧位置后退场，快速展开收起不留幽灵卡片。
- 日期详情从下方进入；滚到底部，最后一位成员的内联路径和完整卡片可见。
- 故意阻断 /marks 图片请求时，详情所有成员图案仍可显示。
- 无动效模式功能可用；原始历史、间隔设置与身份保持回归通过。

## 8. 完成后输出

复现与修复证据、触摸及两引擎结果、长详情与叠卡截图、PR和正式发布资源/历史完整性校验。浏览器touch事件不等于物理iPhone帧率验收。
