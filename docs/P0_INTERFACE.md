# P0：任务、记录与动效收敛

## 1. 背景

保留黑白大字、值日/抬水/日历三页，不做游戏化。先完成用户的 P0：统一代币、三行任务卡、一个主操作、完成后收起且可撤销、三月统计与历史补改。

## 2. 当前仓库状态判断

从 main 的 `0ee7a58` 开始，独立分支 `codex/p0-quiet-task-layout`。既有 Vue 3 / TypeScript / Vite / Vant / Motion for Vue / Reka UI 不变，正式运行环境为 Node + SQLite。

`src/interaction/tokens.css` 原本存在且由 `style.css` 导入；问题是代币覆盖不完整，而不是所有代币都未定义。新增字号、行高、间距、边框、类别色及完整动效曲线。没有新增前端依赖。

## 3. 本轮目标

| Before | After | Why |
| --- | --- | --- |
| 标题、间距和卡片参数各自定义 | 32 / 20 / 16 / 14 / 13 字号，16 / 24 / 32 布局间距，卡片间距12；细边框、16圆角 | 让同类信息稳定对齐 |
| 大字任务页缺少统一负责人/状态结构 | 类别图标、负责人、任务标题、真实状态/轮次、完成圆圈 | 一眼区分任务类型和完成状态 |
| 已完成按钮仍占据主区域 | 回执后短暂确认，再进入默认折叠的已完成组；展开可撤销 | 让未完成任务优先展示 |
| 粒子、飞入加分、游戏排名及姓名老虎机混杂 | 仅完成回执后的小粒子与12ms震动；普通数值/成员状态，无老虎机或加分 | 反馈只解释操作结果 |
| 仅月历和列表 | 三月热力图、四类次数/本轮完成率/连续天数、近五天打卡条 | 图和数字可以相互核对 |
| 往日漏记无法补改 | 本人修正本人、真实创建者修正全宿舍；补记/改时间/删除均留日志 | 修正记录而不改当前业务轮次 |
| 月份回位单独使用270ms曲线 | 与抽屉共用 settle 540/42/0.8 | 减少相同动作的手感差异 |
| 历史展开动画高度 | 静态两层预览，真实记录使用 transform/opacity 交错与移动 | 避免逐帧布局及隐藏按钮误触 |

## 4. 修改范围

- 活跃入口使用的 ChoreBoard、日历、完成反馈、记录、排序及共享动效；旧账号页面只统一 Toast 与全局字号基线。
- `QuietTaskCard` / `TaskCategoryIcon` / `QuietRoundProgress` / `ActivitySummary` / `HistoryEditor`。
- 新增数据库迁移0010，仅新增历史投影与追加日志表。
- `GET /chores/activity` 读取近三月日汇总、最近五天最多500条明细（超出时明确提示，汇总仍完整）。
- `/chores/history`：POST补记；PATCH改时间；DELETE软移除；GET查看原值、修正值、操作人、原因和时间。

## 5. 禁止事项与边界

- 不改顺序抬水、自由值日轮次，不启用 least-completed、到期窗口或新的提醒策略。
- 历史投影不会回写 `chore_tasks`，也不改变当前轮次、抬水游标、负责人或推送任务。
- 修正不允许把原记录转给别人。需要改类别时，应删除错误历史记录再补记正确类别。
- “真实创建者”指创建或恢复管理权限的设备凭证，输入创建者名字不能获得管理权限。
- 本轮没有新增 Android / HarmonyOS 原生功能或验证厂商推送。

## 6. 具体实现

统计区间为本月及前两月，时区统一 Asia/Shanghai。完成总数为有效历史记录次数；本轮完成率仅对自由值日轮次计算；无固定配额的抬水显示“—”。连续天数是窗口内实际有记录的连续日期，当前连续可从今天或昨天往前计，不代表每日义务。

历史投影保留原任务行；修改投影带 revision 与全宿舍 version 的并发校验，追加 audit。删除需要确认和原因；软删除仍保留原值和日志。创建者在提交时再次校验实际管理员身份。

动效采用用户最后确认的90ms按下、360ms释放，240/180ms抽屉进出和共享弹簧。按钮50px高，内部fill transform/opacity完成胶囊转圆；不动画width/height/top/left。对勾为220ms局部显现；8个小粒子360ms，只有成功回执后触发。失败恢复，不做确认。遮罩仅20%黑色，不模糊。完成提示顶部1600ms，已完成组提供更持久的撤销入口。

历史记录展开交错上限400–560ms，不动画容器高度；收起后不保留隐藏的操作控件。月份仍为真实三面板跟手预览，松手共享settle弹簧。禁用按钮不缩放，系统减少动态效果及键盘交互直接显示终态。

## 7. 验收标准

- 320 / 390 / 430px手机及1024px桌面无横向溢出，主操作高度50px。
- 同一任务卡三行信息，完成圆圈直接提交；回执前不庆祝，失败不改状态。
- 完成任务从待办中移除，已完成组默认收起，Toast和展开组可撤销本人可撤销的打卡。
- 热力图、次数、日期、月历和近五天列表一致；抬水不伪造完成率。
- 普通成员不能补改别人，跨宿舍读写拒绝，名字认领不提升为创建者。
- 补改历史和删除投影后，原任务行、当前轮次及抬水待办完全相同。
- 修正日志包含原值、修正值、操作人、原因和时间；陈旧 revision/version 拒绝保存。
- 抽屉、拖拽排序、连续月份预览、错误恢复、键盘和减少动态效果仍可用。

## 8. 验证输出

执行并记录：前端格式/类型/生产构建；history权限与数据不变性；全部业务脚本；新P0 Chromium/WebKit实接口夹具；既有排序、抽屉、导航、月份及双浏览器持久化回归。截图与详细结果保存在被git忽略的 `docs/evidence/p0-interface/` 和既有交互证据目录。物理iPhone/Android/HarmonyOS手感和厂商送达不属于浏览器模拟验证。
