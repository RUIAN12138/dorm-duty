## 使用行为

1. 首访先创建 / 加入宿舍，不自动读取示例。
2. 创建者填写宿舍名、自己的名字、可选室友名单；服务器原子创建成员、30 天排班和当前设备管理员会话。
3. 室友输入邀请码，选择自己和未占用的像素标记，确认后领取成员身份。「值日」`/` 显示本人今天或最近任务；「抬水」`/water` 显示当前负责人和顺序；「日历」`/calendar` 显示完成标记，底部导航切换，各页只保留一项主内容。
4. 创建者通过次级入口「自定义任务」设置三类内容、截止、开始日期、顺序和启用；地板 / 厕所增加星期与连续负责天数。所有正式成员能完成本人任务、定向提醒其他任务负责人。旧模板 / 休息日 / 单日安排接口继续保留，见 [CUSTOMIZATION](CUSTOMIZATION.md)。
5. 六人 `6-402` 示例只在点击「先用游客模式体验」后出现，持续显示游客标记，不能悄悄作为正式宿舍恢复。

选择名字不构成可信身份，当前是宿舍熟人之间的信任式入口。匿名查看不能写；确认选名领取的成员令牌可以完成其绑定成员的任务、发提醒和修改本人标记，不能改设置，也不能调用原管理接口。即使选择创建者名字，也不会获得管理权限。创建者完整令牌保存于当前浏览器，清除网站数据会失去本设备管理权限。所有业务响应使用 `no-store`。

管理员的浏览器会话存储清空后，可以从当前浏览器的持久存储恢复设备令牌；服务重启后服务器仍识别该会话。临时连接失败保留令牌并允许后续管理导航重试，真正无效的令牌收到 401 后清除。不同 URL 的浏览器存储独立，例如 Mac 的 `127.0.0.1` 与手机访问的局域网 IP 不是同一浏览器身份来源。

## 恢复连接后的发布步骤

1. 读取原站点确认身份 / 访问模式，申请短期写入凭据。复用原站点，不创建重复 Site。
2. 用 Sites 官方源码工具同步 `site/`，运行剩余构建 / 产物检查，从同一已推送提交打包。
3. 先在原访问范围部署新版本，确认 `0000`、`0001` D1 迁移和 `/health` 返回 `runtime: cloudflare-worker`、`storage: d1`。对实际 D1 复查绑定限制、批处理原子性、并发抬水及提醒限频，不用本地适配器通过代替。
4. 用 `scripts/seed-cloud-demo.mjs` 单独建立六人示例；平台凭据经隐藏 stdin，不输出管理员令牌。保留成功结果，避免重复创建。
5. 删除旧平台 `API_ORIGIN`，配置示例 `DEFAULT_DORM_INVITE_CODE`。应用新环境时重部署同一已保存版本，不重复保存源码。
6. 按用户免登录要求开放网页入口，不带平台服务凭据运行公网脚本：

```sh
node scripts/verify-minimal-guest.mjs https://lundao-dorm-duty.dapper-eft-1618.chatgpt.site
```

7. 停止本轮隧道 / 网关，再检查创建宿舍、邀请码选名 / 标记、本人三类完成、抬水推进、完成日历、定向提醒、管理编辑、刷新同步及健康接口。原最简入口脚本只覆盖其声明的旧范围，新增三类任务按 [CHORES](CHORES.md) 与 [手机验收](MOBILE_ACCEPTANCE.md) 执行；验收只创建独立假数据，不改原宿舍。
8. 记录原生部署 ID、版本、源码 SHA、D1 和访问范围结果，更新发布说明。iPhone 真机、主屏幕、锁屏 Push 单独验收。
