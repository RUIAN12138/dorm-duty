# v70：设置内容保留与球球聊天连续性

本轮只修改设置内导航、相应加载态、球球聊天收起/提示/长按以及 AI 使用指南。不更改打卡规则、轮序算法、历史记录、主题配色、日历样式、底栏或完成反馈。

| Before | After | Why |
| --- | --- | --- |
| 设置子页被 `v-if` 销毁 | 同一次设置会话内保留访问过的内容，关闭整个设置后释放 | 防止反复挂载、输入丢失、重复请求 |
| 共用滚动位置 | 按页保存滚动位置，新页从顶部开始，返回恢复位置 | 避免子页直接滚到最下方 |
| 切页交叉淡入 | 前进由右进入、返回反向，内容面板不透出另一页文字 | 明确层级与连续运动 |
| 第一次加载只改变按钮文字 | 通知、邮箱、提醒时间各有对应骨架和 transform 流光 | 等待与实际结构对应，已有内容不伪装重新加载 |
| 收起一开始暂停球球 | 球球在返回途中继续当前表情，到落点交接姿态 | 去掉返回时表情静止的一段 |
| 长按 550ms | 长按 380ms，仅成功触发时请求 10ms 轻震 | 缩短等待，滑走或取消不触发；iOS Safari 不支持此震动 API |
| 聊天气泡在球球下方 | tips 从右上方弹出，限制在视口内 | 按请求保留名字框与其余布局 |
| 使用规则散落在简短提示里 | 每次模型请求附经界面核对的使用手册和实时只读上下文 | 指引真实入口，不把使用知识等同执行权限 |

保留减少动态效果/键盘导航降级；隐藏设置页不再接收输入，球球设置隐藏时停止表情巡览，避免保留 DOM 后后台仍改变主页面表情。通知缓存按成员令牌隔离，短时间重新进入不重复取配置；切换身份立即失效。日历订阅恢复配置时重新派生其地址，不跨身份保留地址。

## 回归

- `DORM_CONTINUITY_QA=1 node scripts/check-companion-chat-browser.mjs`
- `DORM_BROWSER=webkit DORM_CONTINUITY_QA=1 node scripts/check-companion-chat-browser.mjs`
- 原聊天默认分支、邮箱 HTTPS 流程、日历数据/历史修正、页面退出检查。
- `node site/scripts/check-companion-ai.mjs`：手册随请求提供；真实数据与操作权限边界、隐私隔离、确认提醒流程保留。
- `npm run typecheck --prefix frontend`、生产构建及改动文件格式检查。

这些检查使用隔离宿舍和模拟邮件/模型，不对正式打卡或提醒做写操作。浏览器引擎中间帧检查不能代替真实手机的触感与生命周期验收。

## 数据排查与发布

先只读比对正式数据库、运行进程实际打开的数据库及发布前备份；不因前端显示空白直接覆盖数据库。发布包只含代码，不含数据库或密钥。每次发布前备份，再对既有打卡、补记/修正、邮箱绑定、聊天记录计算行摘要并检查 SQLite 完整性。发现用户旧记录显示不一致时继续按宿舍、月份、任务和记录定位，不将“服务端记录仍在”宣称为“用户显示问题已解决”。
