# 本轮集中优化验收说明

## 范围

基于main的06b483b提交，保留现有视觉与动作，不增加运行时依赖。验收站点仅使用隔离本机数据，真实业务仍由Node+SQLite服务承担。

| 方向 | 本轮结果 | 验证 |
| --- | --- | --- |
| 历史操作 | 打开时版本、提交快照、删除确认防重、失败保留、换记录/重开/身份隔离 | history-mutation + 实际HistoryEditor内存组件检查 |
| 历史详情 | 首次已打开正常读取，失败禁止旧修订号写入，提供重读 | 实际组件初始挂载/错误/重试接线检查 |
| 请求加载 | 六个管理视图传递取消信号，旧错误/收尾不覆盖新读取，卸载取消 | view-load + API取消检查 |
| 网络状态 | 离线/超时/不可达区分，15秒期限覆盖响应正文，取消不误报 | API fetch/body deadline检查 |
| 通知身份 | 排队关闭/测试与绑定前检查身份，旧操作不影响新设备 | push-identity隔离测试，无真实投递 |
| 账号信息 | 运营诊断读取可取消、依邮箱与创建者身份失效；恢复码初始打开可用 | 类型/构建，账号原回归 |

| 演示验收 | 本机历史补记/修正/删除、版本冲突和修正记录 | review-check隔离适配器检查 |

## 本次及之前已覆盖的主流程

完成/撤销回执，抬水首次遇见与重新完成播放，日历邻月数据，按需统计，后台合并及退避，消息已读，提醒编辑器，标记和任务/轮序草稿保存，会话/邮箱竞态，均保留并纳入统一回归。

## 验证边界

完整web:verify通过38项，包含真实Node HTTP、文件SQLite、定时提醒及两次重启。历史编辑组件接线、浮窗收尾保护补测和验收页类型/生产打包均通过。提交PR前再次执行完整检查及CI中其余非浏览器检查，结果通过。

新增npm run web:test-state，单独执行15项前端状态与生命周期回归，并接入现有GitHub Actions；web:verify复用同一脚本列表。原有业务、浏览器与Android检查继续保留。

本次环境无法启动受支持的浏览器预览，尚不能确认真实CSS中间帧、抽屉触摸、窄屏布局和实体手机表现。真实邮箱/通知提供商投递与系统手机通知未验证。演示接口不等同正式服务上线。

## 顶部提醒与页面连续性更新

- 收到室友提醒时使用上方浮窗，按宿舍/成员记录本机展示回执，刷新不补播。上滑收起、短拖回弹，提供按钮/Escape；点击进入消息抽屉。关闭浮窗不等于已读。
- 日历分栏、日期焦点和列表页码/展开/滚动位置由当前Board保存，跨分栏导航恢复，跨身份不共享。
- 任务详情的提醒入口预填对应室友/任务，读取最新任务后再允许发送，失效任务需要明确重选。
- 邮箱入口优先进入已绑定的上次宿舍或唯一宿舍，多宿舍继续选择，保留正式验证与enter接口。
- GitHub入口放在个人与更多；顶部身份栏与按钮整体下移10px。
- 本轮完整38项回归通过。浮窗手势/列表记忆使用Vue内存组件检查，浏览器视觉及实体手机仍待验收。

## 合并协作

基线为main@06b483b。本PR的请求封装与#57描述的API契约工作在职责上重叠；合并时需要确认顺序并复核前端封装与服务端响应格式。数据库迁移、推送提供商和客户端签名配置沿用现有方案。

提交前补测后台取消后立即前台恢复，避免调度器复用旧flight。浏览器用例已按顶部浮窗及唯一宿舍进入逻辑更新，在本环境未运行真实浏览器；现有CI会执行其浏览器和Android检查。
