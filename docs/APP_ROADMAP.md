更新：2026-10-16。本文保留完整目标，不用局部构建或接口通过代替整体验收。正式网站已更新到 v40r1；最新圆环、完成反馈及日历同步收起已发布。安装版最低发布路径、外部阻塞和 Issues 见 [Android 发布清单](ANDROID_RELEASE.md)，不再以旧网页版本代表当前客户端进度。

## 当前架构和实际状态

最新范围：用户选择 Android / HarmonyOS 只做基础通知，暂不接厂商通道。现有阶段表中的厂商配置项留作后续备选，不作为本轮阻塞；本轮实现与验收边界见 [基础通知](BASIC_NOTIFICATIONS.md)。

Android WebView、HarmonyOS ArkWeb 已加载远程 Vue 页面，Node / Worker 共享业务实现与 SQLite。网页样式和业务页面发布后不需要重新安装客户端；当前 PWA 使用更新提示，在页面内确认更新。修改原生桥、通知 SDK、系统权限、卡片等原生能力仍需更新安装包，首次离线启动也不能当作已支持。

## 第一阶段：通知、更新与客户端底座

| 要求 | 状态 | 完成证据应包含 |
| --- | --- | --- |

| 原生桥和异常恢复 | 本轮补齐加载错误、超时、返回与迟到桥就绪；待真机 | 网络失败→重试、子资源失败不覆盖整个页面、旧导航回调不覆盖新页面、两个平台返回 / 退出 |
| Node 即时及定时通知调度 | 即时队列与个人定时提醒已实现；默认关闭，可选 1–3 个北京时间，Node 独立调度，待正式发布及手机定时接收验收 | 上海时区、幂等、完成后取消、重启补偿、跨宿舍 / 离开宿舍取消、投递失败状态 |
| HarmonyOS Push Kit 通道 | 当前仅极光 SDK 与服务端入口，华为平台配置待办 | 本应用标识、签名、华为 / 极光厂商配置，前台 / 后台 / 锁屏 / 关闭应用真实接收 |
| HarmonyOS reminderAgentManager | 待实现 | 用户明确设置的本地提醒、权限、系统数量限制、修改 / 完成 / 退出后的取消和重启恢复 |
| Android AlarmManager | 待实现 | 仅对有明确时间的本地提醒调度；精确闹钟权限 / 不可用时降级、重启恢复、完成取消 |
| Android 在线连接与后台策略 | 待实现 / 平台策略核对 | WebSocket 只证明在线链路；需要前台服务时必须展示系统通知并提供开关，不能承诺后台永远存活 |
| Web 备用通道：ICS | 私有个人日历源已实现；地板 / 厕所待办、提醒时刻选项、撤销 / 轮换与 10 秒限频 | 日历客户端导入和自动刷新尚待真实设备验收；ICS 不是即时推送，详见 [个人日历订阅](CALENDAR_SUBSCRIPTION.md) |

网络断开、系统权限关闭和终端关机等情况下不承诺 100% 必达。AlarmManager / reminderAgentManager 可处理已设置的本地提醒，不能凭空收到离线后的新催促。ICS 由日历客户端决定拉取频率，不适合紧急“没水了”实时呼叫。相关平台 API 和分发限制在实际接入时以官方文档与真机为准。

| 通知“完成 / 一小时后” | 待实现 | 带最小权限的任务动作，真实系统按钮、服务器幂等确认、过期任务拒绝、稍后提醒可取消，身份变更后不执行旧任务 |

替干、请假、补票、设置变更均需留下服务器时间和操作者记录。只添加数据库字段或画出按钮不算完成。

## 下一步顺序与外部材料

1. 继续两端安装运行、个人日历真实客户端订阅与手机手势验收；个人日历订阅与任务标题左右滑动已经发布。
2. 配置本应用推送与鸿蒙签名，完成两位成员真实系统通知互发，再进入后台与锁屏测试。
3. 实现替干 / 暂离 / 水票与审计，接入通知按钮，最后完善两端桌面卡片。
4. 用容器部署和备份恢复检查收尾；正式发布沿用现有独立备份、迁移、历史记录核对流程。

Android 服务端配置和基础通道模拟器送达已通过，详见 [验收记录](ANDROID_PUSH_ACCEPTANCE.md)。外部待办是 HarmonyOS 服务端配置、华为开发者应用与本项目签名，以及室友机型对应的安卓厂商通道。Android 公开 AppKey 通过本机命令参数和 Actions 变量注入，不写入源码。Master Secret、私钥和服务器密码不进聊天、不进公共仓库。不能用模拟器送达宣布厂商真机后台通知或鸿蒙真机分发已交付。
