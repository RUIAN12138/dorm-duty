# 邮箱账号与邮件提醒

2026-10-16：用户选择个人 QQ / 163 邮箱 SMTP。实现位于当前 Node + SQLite 服务；不是旧 FastAPI 账号入口，也未在历史 Cloudflare 部署开放邮箱 API。SMTP 已私密配置；用户已确认测试邮件实际进入收件箱，并在正式页面完成验证码绑定。手动催促和定时提醒的真实收件验收仍单独记录，不以隔离测试代替。

## 使用方式

- 首次用邮箱获取六位验证码，验证后创建账号；以后同样用验证码登录，不增加密码。
- 可勾选邮件提醒，登录后可随时开关。设置入口是「个人与更多 → 邮箱账号与提醒」。
- 当前已进入正式宿舍的设备可验证邮箱并绑定现有身份。用户 ID、成员关系、标记和历史记录不复制、不重建；同一邮箱可以绑定不同宿舍，每个宿舍仅绑定自己的一位成员。
- 换设备登录邮箱后，从账号里的已绑定宿舍直接进入，不再重新认领名字。未绑定的创建者与普通成员一样，以已验证邮箱、邀请码和正确姓名认领。已绑定身份只允许原邮箱进入。此选择不提供实名或创建者审批保护；邀请码与姓名均已知的人可能先认领尚未绑定的创建者。
- 新版本启用邮箱入口后，所有正式成员均需重新验证邮箱。独立创建者设备凭据已在迁移 0015 撤销，已有邮箱绑定保留；没有有效邮箱授权的旧凭据不能再访问正式业务接口。游客模式保留。SMTP 暂时故障也不会放开正式入口。
- 新建宿舍：邮箱登录 → 创建宿舍，自动成为创建者；房间、管理身份和邮箱关联在同一事务提交，无需再次绑定或恢复。旧创建者不再需要恢复管理权限这一额外验证；未绑定时凭邀请码与姓名认领，已有绑定时由邮箱恢复。
- 首次尚未绑定的普通成员先验证邮箱，再用「邀请码 + 正确名字」认领并自动绑定。这不是创建者审批或实名验证；本轮未擅自引入审批制度。
- 首次绑定会撤销该成员其他旧姓名会话，保留当前设备。退出邮箱会撤销这个邮箱登录会话生成/绑定的成员凭据；其他独立邮箱登录设备不随之退出。
- 邮箱会话 30 天；创建新宿舍可使用有效登录，绑定已有成员身份需十分钟内重新验证。验证码十分钟有效、一次性，单个验证码最多五次错误；同邮箱最短六十秒重发、一小时最多五次，同来源一小时最多三十次，站点验证码一小时合计最多一百次，避免个人发信账号被公开入口刷量。数据库只保留 HMAC，不保存明文验证码；已消费验证码最多保留一天用于限流。

## 通知分工

| 通道 | 本轮用途 | 边界 |
| --- | --- | --- |
| 站内消息 | 原有手动催促和定时消息 | 打开页面同步，原消息阅读、权限规则保留 |
| 邮件 | 开启邮件提醒的已验证账号，接收关联成员的手动催促、定时提醒 | 不要求轮到 App 在线；邮件客户端的系统通知、收信频率与垃圾箱策略由客户端/邮箱服务决定 |
| 极光基础通道 | Android / HarmonyOS App 在线时的补充 | 不接厂商、不承诺系统杀进程或强制停止后即时到达 |
| iOS PWA | 继续现有 Web Push | 不改变现有主屏幕安装与授权条件 |

手动催促邮件的标题和正文均标明发起室友；定时邮件标明“系统自动提醒”。

邮件队列每十秒扫描已提交的业务提醒，按账号 + 提醒 ID 去重，投递前复核宿舍、成员、任务、阅读和定时计划状态。关闭邮件、任务完成/停用、离开宿舍或计划已变化时取消未发送的旧消息。只处理绑定及开启邮件之后的一天内新提醒，不批量补发历史消息。

同账号业务提醒邮件最短间隔一分钟，一天最多五十封；额外催促仍保留站内消息，避免连续敲击刷邮件。测试邮件每分钟最多一次。失败最多尝试四次，持久化退避为一分钟、五分钟、十五分钟；租约超时后可恢复。SMTP 接受仅表示交给发信服务，不等于收件箱到达或用户阅读。网络在 SMTP 接受后、数据库确认前中断时仍可能重复投递；固定 Message-ID 辅助识别，不承诺严格 exactly-once。

## 私密配置 QQ / 163 SMTP

1. 在你自己的邮箱设置中启用 SMTP，取得邮箱提供的 **SMTP 授权码**。如页面要求验证身份，由本人完成。不要把授权码、邮箱登录密码发进聊天、GitHub 或命令参数。
2. 发布包就绪并连接服务器后，将配置脚本放到服务器代码目录，在交互 root 终端运行：

   ```bash
   python3.11 /opt/dorm-duty/incoming/configure-email.py --owner dorm-duty
   ```

3. 按终端提示输入 SMTP 主机、465（隐式 TLS）或 587（强制 STARTTLS）、登录邮箱、发信邮箱与站点源地址。站点源地址保持 `https://8.148.190.114`，不要附加 `/dorm-duty/`；实际部署路径由 `DORM_WEB_BASE` 提供。QQ 常用 `smtp.qq.com`，163 常用 `smtp.163.com`，具体以账号设置页为准。
4. 授权码用不回显的提示输入两次。脚本先验证 TLS 连接和 SMTP 登录（不发送邮件），成功才原子写入数据目录 `email.json`，权限 600、属主 dorm-duty；保留原验证码 HMAC 密钥。它不修改原生推送和 Web Push 配置。
5. 备份数据库与邮件配置后，安装包含新迁移及 `site/runtime/email-runtime.cjs` 的发布包，再重启 `dorm-duty`。运行 `--check` 仅输出是否已配置，不输出地址或凭据，也不表示 SMTP 鉴权成功。
6. 用本人真实收件箱验收验证码、首次绑定、退出重登、测试邮件、同宿舍另一成员的手动提醒与定时提醒。记录服务接受和实际收件时间分别在哪一步；测试过程中不对真实宿舍批量发信。

发信账号通过个人终端填写，未写进示例、仓库或公开 Issue。这里不使用任意地址代发邮件或开发模式返回验证码的接口。

## 发布和恢复

- `0013_email_entry_policy.sql` 增加持久入口策略。首次启用时一次性撤销旧邮箱登录会话和授权映射，保留邮箱绑定、旧设备证明、宿舍、轮序、任务及历史。服务重启不会再次触发全员退出。
- `0012_email_accounts.sql` 是追加迁移；现有表的 ID 和历史记录不改。上线前在线备份，核对任务、完成记录与审计摘要。
- `node site/scripts/build-email-runtime.mjs` 将 SMTP 依赖打包进服务模块，发布服务器不需要现场安装 npm 依赖；许可证随包提供。
- 从未启用邮箱的本地/测试服务继续原入口；一旦持久策略启用，缺少 SMTP 配置也维持邮箱准入，已有有效邮箱授权可继续使用，不能退回旧匿名模式。
- **绑定启用后，不直接回退到不含邮箱认领保护的旧 Node 服务**，否则旧姓名认领端点会绕过绑定限制。恢复应保留新版邮箱保护层，或先在网关关闭姓名认领/创建入口，再恢复兼容版本。不要删除账号绑定表来“修复登录”。

前两组使用隔离 SQLite 和注入邮件传输；浏览器组使用真实 HTTPS、HttpOnly Cookie、SQLite 和 Vue 页面，覆盖窄屏、账号创建、宿舍绑定、跨设备恢复、退出以及按压反馈。它们不证明 QQ/163 SMTP 鉴权、收件箱送达、邮件客户端系统通知或原生 App 真机 Cookie 恢复已通过。

### 前台恢复

同一邮箱登录会话可同时在多个窗口查看宿舍。进入时复用属于该邮箱会话、成员和权限的有效凭据；新窗口不会撤销其他窗口，遗失窗口的凭据保留上限32份。退出邮箱仍撤销这个登录会话的全部宿舍凭据。

任务凭据失效时先核对邮箱，仍登录则自动续接，保留原任务组件和页面状态；邮箱真正过期则直接显示验证入口，不停在“重新加载”错误页。后台中止尚未结束的任务读取，回到前台或网络恢复后重新同步；打卡请求不受此取消影响。本次发布不再次触发全员退出，也不改变邮箱准入策略。

浏览器回归模拟连续focus/pageshow/visibility事件、读取挂起、断网恢复和两类身份失效；这不等同于实体iPhone后台资源回收验收。

## 2026-10-17 邮箱会话统一与运维边界

- 0015 追加 `sessions.dorm_id` 并撤销 `kind=device`，不修改成员、任务、历史和邮箱绑定。客户端删除旧 `dorm-owner-token`；`dorm-email-admin-grant` 是邮箱登录签发的业务授权，不是独立登录方式。Cookie/原生授权到期或退出后不能绕过邮箱准入。旧设备未绑定邮箱时明确提示重新验证并用邀请码、姓名认领。
- 解绑只撤销当前宿舍、当前成员的业务会话和通知订阅；保留邮箱账号、其他宿舍授权和历史。解绑仍要求十分钟内邮箱验证。独立设备的本宿舍授权同时失效，其他宿舍不受影响。
- **多验证码并存**：重发不撤销其他验证页面已发送且未过期的 challenge；每个码仅能在发起它的页面（challenge_id）验证一次，十分钟到期、最多五次尝试。当前页面点重发后应使用新邮件的码，其他仍打开的验证页面可继续用各自的旧码。本轮未改成按邮箱跨 challenge 搜码，也未宣称成功验证会清空其他页面的码。邮件和问号提示说明此规则。
- 纯文本与 HTML 双格式同时发送；验证码 HTML 独立加粗、纯文本仍以清楚标点隔离六位数字，用户名与任务正文转义。测试邮件明确注明测试；手动催促保留发送人。
- `runtime_metrics` 只记聚合计数和时间：verify_attempt/success/failed、mail_attempt/accepted/failed、rate_limited，不记地址、验证码或邮件正文。`GET /email/operations` 限已登录创建者；账号设置显示历史发送失败、待重试和最终失败数量。失败另向服务 journal 写入 `smtp_delivery_failed` 结构化错误，便于管理员查询。它是站内/日志告警，未接短信等站外告警；SMTP 接受仍不等于收件。
- 发布包写入 `site/release.json`（版本、提交、构建时间），`/health` 返回 release，设置显示同一版本。源码本地运行显示 development。
- Worker 默认拒绝所有业务 API，只有 Node 邮箱网关通过检查后才在进程内部传入不可序列化的 Symbol 准入凭证；浏览器请求头以及 Wrangler 的字符串、布尔值或 JSON 配置均不能开启。不能把旧 Worker 单独作为生产后端部署。
- D1 选择保留为**只读历史归档**，不再写入、同步或作为灾备自动切换目标。公开 routes 与 Pages 保持下线，仓库禁用旧发布入口；不删除用户数据。未来恢复归档只能先导出到隔离环境审查，再走当前 Node 邮箱网关，不能重新公开旧服务。
- 发布前备份 SQLite、记录行摘要和当前 release；回滚只切换到仍具邮箱准入的兼容服务，禁止还原数据库覆盖新的用户写入。0015 不回滚删除列；发生回滚后不得重新启用 device 登录。具体命令见 SERVER_DEPLOYMENT.md。
