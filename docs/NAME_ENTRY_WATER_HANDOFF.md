# 姓名入口、抬水重排与交接动画

本轮保持黑白大字、三页布局和已有完成 / 撤销交互。发布包：`20261016-name-handoff-v32`。正式服务器仍为 v31，本文不代表已发布或真机验收。

## 已确认的产品规则

1. 正式宿舍：邀请码后输入名单中的完整姓名，服务器精确匹配。游客仍可选人，只读。有效身份可刷新恢复，主动切换身份重新输入。
2. 姓名不是密码；知道邀请码和姓名的人仍可领取该姓名的成员身份。成员令牌不能提升创建者权限，也不能直接操作其他成员的完成 / 撤销。
3. 保存抬水顺序后立即重算当前待办：最近一次已完成者在新顺序中的下一位；没有历史取第一位。历史完成记录不重写。同日可有多次真实抬水。
4. 打卡成功才产生交接事件。重排不产生抽奖，不随机选择实际负责人。
5. 本机按宿舍 / 成员存最高已播放轮次。首次读取旧历史只建立基线；新交接在首次打开抬水页时播放一次。离开、刷新、普通轮询、撤销旧轮次不会重复播放。清除本机网站存储后会重新建立基线。

## 接口和兼容

- `/chores/claim` 要求 `invite_code`、`nickname`，可选 `member_id` 仅用于兼容显式身份约束，不能绕过姓名匹配。旧页面仅提交 ID 返回明确更新提示。错误名字不发放会话，普通领取创建者姓名也不授予管理凭据。
- `/guest/dorm` 匿名正式查询仅返回概要与空名单；正式完整名单和旧 `/guest/tasks` 需该宿舍有效令牌。游客仍可读取演示名单。
- 新建宿舍拒绝重名。既有重名不静默选择第一人，返回核对提示；本轮不批量修改既有姓名或失效全部令牌。
- 抬水重排沿用任务 ID 和轮次，只改未完成任务负责人及快照，取消旧接收者未发送提醒并标记旧提醒已读。运行时发送前再次检查任务负责人。已发送到系统的旧通知不能撤回。
- `water_handoff` 来自真正完成记录，包含 `id/sequence/from_member_id/completed_at`。它独立于宿舍版本号，提醒、设置或轮询不制造动画事件。
- 无数据库迁移，无新增依赖，不修改部署凭据或推送密钥。

## 验收

- `site/scripts/check-name-entry.mjs`：姓名、名单隐私、旧 ID 领取、创建者隔离、失效成员、重名，25 项。
- `site/scripts/check-water-reassign.mjs`：无历史起点、最近完成者后的新序、过期按钮、版本冲突、完成历史、提醒、并发单一待办，29 项。
- `scripts/check-entry-handoff.mjs`：真实 Chromium / WebKit 中验证连续滚动、最终姓名、普通轮询不打断、切页 / 刷新不重播、减少动态、任务上下文、下一位预览、关闭提醒仍可见时间。
- `scripts/verify-chores.mjs`：两个独立浏览器配置、临时 HTTP / 文件 SQLite，31 组流程通过，含错误姓名再重试、已加入宿舍恢复、三类详情可点、轮序保存、真实完成、本人撤销、提醒、跨页手势和服务重启。
- 79 项交互基础、轮序边界 Chromium / WebKit 各 30 项、原业务 / 轮次 / 系统推送 / 定时提醒 / 日历订阅回归仍需与本轮 CI 一并保持通过。
- 上述浏览器与隔离数据库检查不代替实体 iPhone / Android / HarmonyOS 帧率、触感、锁屏通知与正式发布后验收。
