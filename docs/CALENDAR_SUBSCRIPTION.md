# 个人日历订阅

日历订阅将当前成员自己的地板、厕所待办提供为私有 iCalendar（ICS）订阅。它适合把日程显示在系统日历；系统日历按自己的频率同步，不能代替实时室友提醒或离线推送。抬水不进入固定日历，因为当前规则是没水后再由下一位完成。

## 使用

正式成员打开「… → 系统通知 → 日历订阅」，生成订阅地址后可复制，或在支持的设备上点「添加到日历」。地址是仅本人可管理的私有能力：服务端只保存 SHA-256 摘要，界面不在读取设置时再次显示完整地址。请勿转发。丢失地址时可重新生成；原地址随即失效，需要在日历客户端移除旧订阅并添加新地址。

「沿用定时提醒」是可选项，只把本人已启用的提醒时刻写入日历事件。更改后可单独保存，原订阅地址保持不变。关闭个人定时提醒会在下一次同步时移除 ICS 闹钟。

## 接口与权限

- `GET /chores/calendar-subscription`：读取本人设置，不返回订阅凭证。
- `POST /chores/calendar-subscription`：创建或轮换地址；响应中的路径只返回一次。
- `PATCH /chores/calendar-subscription`：用版本号更新提醒选项，不更换地址。
- `DELETE /chores/calendar-subscription`：撤销地址。离开宿舍或切换当前宿舍也会自动撤销。
- `GET /chores/calendar/{secret}.ics`：日历客户端匿名读取该成员自己的待办；10 秒内重复同步会收到 429。

修改接口需要当前成员会话，服务端使用 compare-and-swap 版本号阻止旧界面覆盖新设置。读取订阅文件不需要登录，因为日历客户端无法携带宿舍网页会话；地址本身是 256 位随机 bearer secret。服务器 Nginx 对该路径关闭访问日志，并将该路径错误日志定向到 `/dev/null`，避免把订阅地址写入普通请求日志或上游错误日志。

输出符合 RFC 5545，包括转义、UTF-8 75 octet 行折叠、稳定事件 UID、完成状态刷新版本和可选 DISPLAY 闹钟。自由轮次任务显示为当天待办，不会为了日历读取创建新轮次；按日排班使用实际安排日期。只展示本人未完成的地板 / 厕所任务，不包含成员名单、邀请码、抬水任务或账号会话。

## 边界

更新取决于日历服务端的订阅刷新频率，完成打卡后未必立刻从所有设备消失。相同原因也意味着 ICS 闹钟不是紧急提醒通道；抬水催促继续走系统通知。接口和本地集成测试通过不等同于苹果、安卓或鸿蒙日历客户端都完成导入及定时提醒验收。

参考： [RFC 5545 iCalendar](https://www.rfc-editor.org/rfc/rfc5545)。
